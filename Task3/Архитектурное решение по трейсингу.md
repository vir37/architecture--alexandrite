# Анализ системы

Необходимо покрыть трейсингом все участки, которые создают заказ или меняют его статус, или предоставляют функциональность для межсервисного взаимодействия.
Поэтому элементами системы для внедрения трейсинга должны быть Shop API, CRM API, MES API, Message Queue (RabbitMQ).

Предлагается отслеживать следующие данные:
1. Идентификатор заказа
2. Источник происхождения (в системе возможно создаение заказа как обычным покупателем через интернет-магазин, так и компаниями партнерами через API)
3. Статус заказа до обработки
4. Стасту заказа после обработки
5. Время поступления запроса в сервис
6. Время обработки 

# Мотивация

Логирование полного жизненного цикла заказа может оказаться накладным в плане хранения большого объема информации, так и зачастую избыточным.
Кроме того, разбор инцидентов по логам в распределенной системе может оказаться технически сложным: тяжело восстановить по логам из разных систем
весь жизненный цикл заказа. 
В этом случае на помощь приходит трейсинг. К тому же он может быть активируем по требованию, для наблюдения за поведением системы при определенных условиях.
Трейсинг позволит получить легко получить полную картину прохождения заказа от создания до выдачи заказчику.

Да, вероятно трейсинг повлияет на определенные метрики, т.к. предполагает дополнительную работу с заказом. Так например, может возрасти _"CPU %"_,
_"Memory Utilisation"_, а также "Response time". Но тем не менее (особенно при временном использовании данного инструмента)
польза от него при разборе неочевидных и несистематических ошибок будет большая.

# Предлагаемое решение

Предлагаемое решение основывается на фактически отраслевом стандарте OpenTelemetry - платформе с открытым исходным кодом,
предоставляющей стандартизированный способ сбора, обработки и экспорта телеметрических данных-сигналов (метрик, трассировок и журналов).

Для реализации сбора и обработки трассировочно информации необходимо:
1. Развернуть инстанс Jaeger с коллектором All-in-One	
2. В сервисы, с которых предполагается собирать трассировочную информацию (Shop API, CRM API, MES API, Message Queue) внедрить экспортеры трассировок.
3. Настроить экспортеры на работу с развернутым сервисом Jaeger.

[Доработанная диаграмма контейнеров](https://github.com/vir37/architecture--alexandrite/blob/solution/jewerly_c4_model.drawio)

# Компромиссы

Из возможных сложностей при внедрении трейсинг видится необходимость доработки элементов системы на сбор и экспорт данных телеметрии.
Это потребует отвлечения существующих разработчиков от текущих задач, либо привлечение дополнительных разработчиков.

# Безопасность 

Для обеспечения безопасности данных трейсинга и реализации аутентификации и авторизации при доступе к Jaeger-UI можно внедрить OAuth sidecar proxy
например с применением KeyCloak.
